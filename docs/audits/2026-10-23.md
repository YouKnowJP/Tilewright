# Full-game audit — 23 October 2026

Release: **v0.24.1**. The audit exercised the actual browser application through
ordinary clicks, keys, touch input, downloads, imports, and real winning routes.
Destructive save checks used disposable browser contexts, never existing player
saves. The published site was also inspected interactively in the in-app browser.

## Findings and fixes

1. **Trailhouse phone overflow in WebKit.** A restored commission’s longer label
   forced an implicit minimum grid width. The commission page measured **460px
   on a 320px viewport**, and also overflowed at 390px. Grid tracks now use
   explicit zero minimums and labels can shrink. The page fits both widths, as
   well as tablet, desktop, and short landscape layouts. Regression checks
   select the longest restored commission label and measure every visible
   Trailhouse game dropdown. Full commission and festival play still passes.
2. **Unrelated screen-reader instructions on game menus.** Mapmaker’s keyboard
   help lived outside the hidden editor. It appeared in the title/library
   accessibility tree. It now belongs to the editor, where the editable map
   retains its `aria-describedby` help. Regression checks cover both directions
   between Mapmaker and the game menu.

Two initial live-check failures were test assumptions: WebKit may finish audio
startup after the click returns, and public hosting correctly enables play links
that are disabled on localhost. The checks now wait for the audio result and
assert the appropriate link behavior for the tested origin. These were not
changes to gameplay or the sharing feature.

## Limits and reproduction

These checks found and fixed the issues above; they cannot prove that every
possible player-created map, random seed, device, or future browser is bug-free.
Mobile checks use browser viewports/touch emulation. Controller polling is tested
with simulated standard-controller input. Physical devices, real controllers,
and actual screen-reader sessions are not newly certified. Audio API behavior
is checked; perceived sound quality is not a listening test.

Run `npm run verify` in `Tilewright` for syntax, model/storage/server/build tests.
With the separately installed Playwright development tooling and Chrome, start
`node serve.mjs` and run `npm run test:browser` for all 25 families. Individual
family exports accept a browser type and `baseURL` for targeted live checks;
Firefox/WebKit launches omit Chrome’s `channel` argument. Firefox viewport/touch
checks omit its unsupported `isMobile` launch-context option.
